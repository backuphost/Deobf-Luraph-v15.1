# Luraph v15.2 (work in progress)

> Notes for the v15.2 work in this repo. Same rules as CLAUDE.md: a reference,
> not a changelog; keep it lean. The v15 plugin (`deobf/obfuscators/luraph_v15/`,
> LURAPH.md) is the base; this file lists only what differs in v15.2.

## Status

`python deobf/deob.py examples/v15.2/sample.luau --no-pypy` (~2 min 40 s) passes
every Luraph v15.2 start-up probe and the script's own environment and
executor checks, runs up to the script's key-server request and writes a
**lifted file** (about 27,000 lines, 79 functions, 51 unlifted blocks, 66 unstructured jumps; it parses). The file
holds Luraph's start-up code and the script's own code (a JNKIE key-system
loader: its checks, the request, the handling of the reply). It is not a
clean script:

- the main function is one control-flow-flattened function of ~11,000
  instructions (Luraph's probes and the script's code together). The
  structurer copies regions that several states reach (the request code is
  there several times), about 65 places are `error("devirt:
  unstructured jump to block_N")`, and the file does not compile as one chunk
  (the main function needs more than 255 registers);
- code the traced run did not take ends in `error("devirt: ...")` where it
  needs a value only a run has: `key register set from a register whose value
  the run did not record` (86 places, most of them copies of 7 instructions of the main function) and `jump to the value of rN, which the
  traced run did not record` (11). Such a branch re-keys the VM or
  jumps with a value computed from what the probes returned: in a correct
  environment it is either a tamper path or an alternative the run did not
  need. Constant-only re-keyings on untaken paths (`r3 = 82796; r3 = r3 +
  13744156; Q = r3`) are not computed either (facts do not fold arithmetic);
- the run stops at the key check: `request({Url = "https://api.jnkie.com/api/
  v1/luascripts/precheck/...", Method = "POST", Body = <SCRIPT_KEY>})`. Nothing
  is sent and no reply is made up; the trace continues with the usual
  symbolic stand-in for the response (its "PC-DENIED" branch), then the
  loader's deliberate stop (`#0`: "attempt to get length of a number value").
  What the server would deliver after a valid key is not in the file;
- `examples/v15.2/sample_src.luau` (a fly script) is not the source of the sample.

`--no-devirt` gives the behaviour trace (~9 s).

## Sample

- `sample.luau` (1,053,039 bytes): a `getgenv().SCRIPT_KEY = ...` line, the header
  `-- This file was protected using Luraph Obfuscator v15.2`, then a container
  `return setmetatable({...}):A()(...)`: it decodes two blobs, `loadstring`s a
  238,585-byte one-line VM chunk (chunk name `Luraph`) and calls it with a buffer.
- The chunk has 17 dispatch loops in four VMs (`vmmap.find_dispatchers` order):
  1-4 (maker is a `local function`, interpreter inside `pcall`), 5-10 (stack
  machine), 11-13, 14-17. Only the last VM runs before the script stops; its
  root proto is Luraph's probes and the script's main function in one function.

## Shape differences from v15

- **Closure maker, three levels**: `function(t,W,m,a,X,V,E,E,c,k,_,R,Y,F)` (VM
  object, frame size, entry pc, mode, per-proto instruction arrays) returns the
  maker `function(Z,Z,Z,J,i,U)` (number seeds of the decryption state and the
  upvalue list `i`), which `return function(...)` the interpreter. The proto
  key is the opcode array of the first dispatcher (`vmmap._return_key`). The
  outer function runs when the lazy constant decoder deserialises the proto: a
  closure op's constant `k[pc]` IS the maker function; it calls it with the
  argument table `a[pc]` (`{seeds..., [0]=count, [-1]=slot of the upvalue
  list, [-2]={index, kind, extra triples}}`).
- **Loop function ("staged" layout)**: `if E==82 then W,Q,Wh,mh=m,J,Z,E; while
  true do ... end else Wh,Q,W,mh=Z,J,m,E end; if mh==74 then while ...`
  (`Stepper.staged`, `pre`, `kmode`). The seeds are mutable key state (`Wh`,
  `Q`: operand decryption, `Wh=R[x]`).
- Handlers build multret packs themselves (`G={n=C-h+1}; table.move(R,h,C,1,G)`),
  opcode trees can have statements around a nested test (`M=nil; if m>=46 ...`).
- **Flattening, two layers** in the main function: hub jumps through a jump
  register (`r219 = target; jmp hub; pc = r219 + 1`, the v15 mechanism) and a
  state variable (`r81 = 252`, a binary tree of `if r81 <= k`).
- **Keyed jumps**: `pc = R[x]` where `R[x] = bxor(K, <result of a probe>)`.
- **Key registers**: the interpreter locals that start as the maker's number
  seeds (`Q`, `Wh`) are re-keyed by ops `Q = R[x]`, read back by `R[x] = Q`,
  and XORed into *keyed* range decryptors (`C = bxor(F[pc], band(bxor(Q,
  band(rshift(Q, 29), 7)), 0x1FFFFFFF)); h = X[pc] + 1; for 1.._[pc] ...`: it
  decrypts the operands AND opcodes of any range, not only the next
  instructions), keyed string decryptors and keyed operand decoders. The
  register holds a hash of what the probes returned: the code behind a
  re-keying only decrypts with the value of a run whose probes passed. There
  are also pairs of plain decryptors for one range with keys that differ by
  one, behind a check of a run-time value: only one side is real.
- **Lazy constants** read their operand from the array at key -2 of the
  constant array (`a = V[-2][slot]; V[slot] = decode(pool[a], ..., a,
  V[-1])`); v15 keeps it at key 0.
- **Register-table checks**: the start-up code passes a function's own
  register table to a check closure (`check(R, key)`: `type(R) == "table"`,
  `getmetatable(R) == nil`, `pcall(setmetatable, R, nil)`, then an upvalue
  becomes `bxor(key, K)`) and calls `setmetatable(R, nil)` on it directly.
  These are not LPH_ENCSTR decryptors: nothing is written into the frame.
- **Script functions kept as plain Lua** in the VM object: `function(...) return
  function(seeds, ups) local a = ups[1] ... return function(...) <state
  machine> end end end` (12 in the sample; `vmmap.plain_factories`).
- The VM object also holds library functions (`[36]=Color3.new`,
  `[6]=vector.create`) and small probe functions (`Z=function(t,...)
  (...)[...]=nil end`, used as `pcall(t.Z, ...)`).
- The start-up code inspects the VM object itself (`for k, v in t`, `type`,
  `debug.info(f, "sl")`): `luraph_vm` in the lifted file.
- Tamper response: a proto gets the string pool and four instruction arrays,
  scrambles them and spins forever (pure VM code, no environment access: the
  trace ends in "endless loop in the script's own code"). A dump taken after it
  has a scrambled string pool: only dumps of passing runs can be lifted.

## The script's own checks (this sample: a JNKIE loader; all pass now)

They are the script's code, not Luraph's, but a wrong answer ends the run the
same way (a `warn` and a deliberate error), so they decide how much runs:

- `game:IsA("DataModel") == true` and `game:IsA("Folder") == false` (PC-R01);
  `workspace:IsDescendantOf(workspace)` and `workspace:IsAncestorOf(workspace)`
  false (PC-R02): envlog answers `IsA` from the API class tree for instances of
  a known class and the two others from the known hierarchy (`classIsA`,
  `CHAIN.descends`; a class only guessed from a child's name and an unknown
  parent chain keep the default `true`);
- `getrawmetatable(setmetatable({}, {__metatable = "locked"}))` must be the
  metatable, `setrawmetatable` must take effect, `clonefunction(f) ~= f` with
  the clone working like `f` (PC-E01..E03): the runtime's natives
  (`__LPH_NATIVE`, devm/luau_cli.patch) are used when present;
- `pcall(request, opts)` where `opts`, `opts.Url` and a header key carry
  `__tostring` / `__concat` / `__index` traps: `request` reads its fields raw
  and raises for a non-string (and non-proxy) `Url`, `Method`, `Body`, header.

## Environment probes v15.2 added (all pass now)

Any failure ends in the tamper response; `--cfg top_thread` (set by the driver
when a VM has the nested maker, `patch_entries(..., shapes)`) switches on the
thread model they need.

- **C stack budget.** A function recurses through `__index` and expects count
  198 and 199 to be reachable (a lazy constant decode at 198 costs one more C
  call). The script thread must start like a Roblox script thread, with no
  parent thread (nCcalls 1): envlog resumes it with `resumetop` (runtime patch
  devm/luau_cli.patch; `build_luau.py` alone does not add it, the trace header
  says so when it is missing). pcall costs no C level in this Luau build.
- **Datatype battery** at that depth, and again ~11,000 and ~20,000 Lua frames
  deep: CFrame constructors and methods, Vector3/Vector2 methods, UDim/UDim2,
  Enum, Path2DControlPoint, Random. A missing member is an error = tamper.
  `type(Vector3.FromAxis(Enum.Axis.X))` must be "vector".
- **Threads.** `coroutine.resume(co)` of a function that waits must leave `co`
  "suspended", also for `task.spawn`; `task.defer/delay` threads are suspended;
  a thread in `signal:Wait()` stays suspended (`doWait`, `CHAIN.sleepers`,
  `CHAIN.parked`, `CHAIN.wake`).
- **Error texts.** `folder.FindFirstChildOfClass(UDim.new(...), n)` must raise
  "Expected ':' not '.' calling member function FindFirstChildOfClass".
- Research: instrument the chunk with table operations only and log through a
  `--cfg plugin_rt` end hook. A Lua hook function per dispatch head is fine if it
  iterates with a generalized `for` (`for k, v in next, t` costs a C level).

## Lifter (what the v15.2 paths do; all guarded by the nested maker shape)

- **Hooks** (`driver.patch_entries`, table operations only):
  - maker: `__MK[1]=function...end; <__PF, __PK, __made, captures>; return __MK[1]`;
  - function around the maker (`maker_info` "outer_ret"): `__MK[2]=...;
    __PM[__MK[2]]=F; __PA[F]={__seq, __maker, ["^name"]=its values}`: every
    deserialised proto is captured, also when no closure of it is made;
  - plain-Lua factories: `__MK[3]=...; __PM[__MK[3]]={__at="<chunk>@l,c",
    ["^name"]=...}`;
  - jumps to a register's value (`vmmap.register_jumps`): `__JT[F][pc]=target`
    (false once two targets were seen), dumped as `"jumps"`.
- **Dump** (envlog `dumpProtos`): a maker function is `{"lf":n,"mk":<proto key
  or factory record>}`. A proto deserialised by a constant request has
  `"__late"` and no `__seq` (not stable between runs); its tables are reached
  through the maker's path (`seq,k,9365,<captured name>,...`:
  `Dump._maker_paths`, `PathResolver`, envlog `decodePath`). Each dump starts
  from the protos the script made (`CHAIN.paBase`). Live answers carry `"protos"`.
- **Closures** (`make_closure_nested`): the child's maker AST runs with the
  closure op's arguments in the outer scope rebuilt from `^name`
  (`VMModel.outer_scope`, `Dump.margs`); the root uses the maker-level capture
  (`scope_from_capture`). `unpack` of a dump table reads the path's own writes
  first (the upvalue list is written into `a[pc]`).
- **State registers** (`Program._walk`, `propagate`, `State.sregs`): a register
  that undecided branches compare (ordered) with >= `STATE_COMPARES` (8)
  distinct integer constants; its value, where the facts know it, is part of
  the walk state, so each block is walked with the dispatch tree decided.
  Without it the main function's walk does not end (200,000+ nodes; with it
  ~12,000).
- **Key registers** (`vmmap.key_registers`, `Stepper.key_locals`): their
  values are carried in `State.locs`, so every step sees the key of its path.
  The driver's hook records the register value at each `K = R[A[pc]]` in the
  same table as keyed jumps (`__JT[proto][pc]`, false once two values were
  seen; an instruction is one or the other); a set from a register takes that
  value (`Stepper._carried`), and without one the path ends ("key register
  set from a register whose value the run did not record"). Without this a
  keyed decryptor ran with the initial seed and scrambled code that was
  walked already (there is one overlay per proto, in visiting order).
- **Register-table checks** (`FrameRef`, `frame_call_inert`,
  `frame_param_inert`): a register that holds the frame, read as a call
  argument, becomes a `FrameArg`. Such a call clears every register fact
  (the callee could write any register) unless the callee provably only
  looks at the table: a library function known by a builtin fact
  (`("t", "g:<name>")`: type, typeof, getmetatable, rawequal, setmetatable,
  also through pcall), or a closure whose walk shows the parameter only
  reaching those (a taint dataflow over its IR; undecided while constants are
  missing: assumed harmless in request walks only). It renders as `{} --[[
  the VM's registers ]]`.
- **Lazy constants**: `operand_array(t)` (key 0, else -2) decides whether a
  decrypted operand needs a `slot@v` request; envlog's decode does the same.
- A register that also holds computed values is never made a jump register
  (`reg_nonnum`): a jump through it without a recorded target ends the path
  ("jump to the value of rN, which the traced run did not record").
- **Keyed jumps**: a symbolic next pc takes the target the run recorded
  (`observed_jump`). Right only because the probes passed in that run.
- **Plain-Lua functions** (`make_closure_plain`, `PlainProto`): lifted with the
  LPH_JIT machinery (`JitModel`); not a state machine -> source text.
- A call of a jump/state register that only ever held numbers ends the path
  (junk behind an undecided check; without it the first constant round took
  80 s); proto arrays in a register are `VMCrash`.
- `devirt.py <src> <protos> --chunk C --raw KEY | --op KEY MODE:PC` work on a
  chunk. Offline walks stop at "needs a constant that is not decoded yet"
  where the pipeline asks the live harness (constants fetched during the
  last lift are not in the saved dump).
- Not handled: the first VM (`local function` maker) and the stack VM (no proto
  of them is made in the sample's run), restoring arrays scrambled by the
  script's own `LPH_CRASH()` (envlog's copies assume a proto table).

## Reproduce

```
python3 deobf/deob.py examples/v15.2/sample.luau -o OUT/sample.out.luau --debug --no-pypy
python3 deobf/obfuscators/luraph_v15/devirt.py examples/v15.2/sample.luau OUT/sample.out.protos.json \
    --chunk OUT/sample.out.chunk_*.luau --raw 1      # or --all out.luau (~2 min) / --op 1 141:9365
```

- After a `--debug` run `*.protos.json` is the dump of the last constant
  round; a dump of a run without the key-register hook has no key values and
  its walk ends at the first re-keying.
- `DEVIRT_ORDER=1`: visiting order (`ORDER n mode:pc sr=<state registers>
  op=`), `RESTART #k` with the jump/state registers, `INERT` verdicts.
  `DEVIRT_WATCH=pc,pc`: which instruction writes those slots of the
  instruction arrays (a decryptor that hits code walked before = junk or a
  wrong key).
- Checks of the result (`research/compile_check.py`, `scope_check.py`,
  `active_locals.py`): it does not compile ("Out of local registers ...
  exceeded limit 200"), 2 out-of-scope names (`A_0`, `A_1`: loop pseudo
  variables on paths that end in an error marker), max 321 active locals.

## Open

- Structure of the unflattened main function: copies of shared regions,
  ~65 unstructured jumps, the 200-locals / 255-registers limits.
- Key registers as pseudo-registers that are state registers (`sregs`):
  facts would carry constant keys (also on paths the run did not take), the
  IR would show the data flow (`key = r3`, `r4 = key`) instead of the run's
  constants, and only a keyed decryptor would need the number.
- One overlay per proto: a decryptor on an infeasible path still changes
  what later steps read. `DEVIRT_WATCH` shows such writes.
- The first VM (`local function` maker) and the stack VM: no proto of them
  is made in the sample's run.
